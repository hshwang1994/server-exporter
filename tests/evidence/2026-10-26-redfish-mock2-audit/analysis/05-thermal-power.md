## 7. Replay·테스트 허점 (숨겨지는 오류, 과도한 default/stub, 미커버 경로)
- `_make_section_runner` 는 "200 + placeholder 데이터" 를 success 로 둔다 — 전원 Off(`05-thermal-002`·`05-power-001`)와 Absent 0 °C(`05-thermal-001`)는 어떤 재생으로도 실패로 안 잡히고, 1차 golden 은 오히려 그 값을 고정한다.
- 미러 밖 경로는 재생 404(README 한계 4): CSUS multi_node 의 11건이 실장비에서 400/500 이면 `multi_node.errors` 가 생긴다 — `05-power-004` 제안이 그 의존을 없앤다.
- 재생은 `ReadingTime`·값이 고정 — EnvironmentMetrics 522 W vs PowerControl 516 W 같은 시점차·변동은 보지 못한다(두 경로를 동시에 쓰지 않아 영향 0).
- Tier 2(`tier2_replay.py`)는 `_get_impl`/noauth/realm seam 만 바꾸고 `_get` 캐시는 실제 코드 — Tier 1/2 power·thermal 18/18 동일. Tier 0 의 테스트 격리 결함(baseline README)은 power/thermal 테스트 밖.
- 새 실측 모양 fixture 부재(회귀 공백): iLO `ACPowerLost` PSU(UnavailableOffline/Critical), XCC3 입력 0 W PSU(Enabled/Critical), 전원 Off(PSU Absent placeholder + 전 센서 UnavailableOffline), iLO Absent 온도 슬롯, XCC3 `PowerControl` 3건(Server/CPU/Memory), XCC3 ThermalMetrics 무이름, iDRAC9 `SpeedPercent.SpeedRPM` 팬, Lenovo 패딩 모델 — 모두 2차/1차 미러에서 축약 recording 가능.
- `_fan_rpm_from_sensors` 는 URI 에 'fan' 이 든 센서만 GET — 이름 규칙이 다른 펌웨어면 조용히 reading null(발동 사례 RMC 뿐, 테스트 없음). `_telemetry_total_power` 도 report URI 에 chassis id + 'totalpowerconsumed' 가 있어야 찾는다(2차 동일 규칙 확인, 다른 규칙 미검증).
- `PowerControl[0]` 선택: XCC/XCC3 는 3건(Server/CPU/Memory Sub-system)이고 [0] 이 서버 전체 — 순서 의존이지만 18/18 성립; 순서가 다른 fixture 가 없어 규칙(`PowerCapacityWatts` 를 가진 항목 우선 등)의 필요성은 미검증.
